    Configuration¶

    Every YAML file in config/ has a corresponding pydantic model. Loading any file that fails validation raises ConfigError and the daemon refuses to start. Secrets are referenced as ${ENV_VAR} placeholders; the loader resolves them from the process environment.

    watches.yaml¶

    # Multi-root watcher configuration.
#
# Each entry declares one watched root. The dispatcher walks the union of
# these roots; each root has its own destination tree and its own rule set.
#
# Path semantics:
#   - `path` and `destination_root`: filesystem locations the daemon
#     watches / writes into. Use absolute paths in production
#     (`./test-watch` is convenient for local development; on a NAS
#     point at `/volume1/docs` or wherever your real data lives).
#   - `rules_file`: a relative value resolves against THIS file's
#     directory (i.e. `rules.yaml` means "the rules file next to this
#     watches.yaml"). That keeps the same YAML working identically
#     when the daemon is launched from the repo root, from a Docker
#     container with `WORKDIR /app`, or from a systemd unit that
#     defaults `WorkingDirectory=` to `/`. An absolute path is
#     respected verbatim - useful for a multi-tenant deployment with
#     a shared rule store.

watches:
  - path: ./test-watch
    destination_root: ./test-watch
    recursive: true
    rules_file: rules.yaml
    unsorted_dir: _unsorted

    See WatchesConfig and WatchConfig for the full schema.

    llm.yaml¶

    # LLM provider configuration.
#
# Default targets Google Gemini Flash Lite via Gemini's OpenAI-compatible
# endpoint. Switching providers is purely a config change:
#   - OpenAI:    base_url: https://api.openai.com/v1
#   - Ollama:    base_url: http://localhost:11434/v1, model: llama3.1:8b
#   - vLLM:      base_url: http://<host>:8000/v1
#   - LocalAI:   base_url: http://<host>:8080/v1
#
# Tunable defaults live in src/taxonomaid/config/defaults.py. Every
# field below is OPTIONAL; if you remove an entry it falls back to (in
# priority order):
#   1. an explicit value here,
#   2. an environment variable like TAXONOMAID_LLM_<FIELD> in .env,
#   3. the default in defaults.py.
#
# `api_key` is the only required field. Reference secrets via ${ENV_VAR}.

api_key: ${GEMINI_API_KEY}

# Override examples (uncomment to take effect):
# model: gemini-3.1-flash-lite
# base_url: https://generativelanguage.googleapis.com/v1beta/openai/
# request_timeout_s: 30.0
# max_excerpt_chars: 262144       # cap on the character length of the
#                                 # text excerpt fed to the LLM (default
#                                 # 256 KiB, ~64 K tokens). The legacy
#                                 # `max_excerpt_bytes:` key is accepted
#                                 # as an alias.

# thresholds:
#   auto_move: 0.75
#   auto_create_folder: 0.85
#   auto_promote_rule: 0.97

    See LLMConfig and Thresholds. Switching providers is a config change; any OpenAI-compatible base URL works (Gemini, OpenAI, Ollama, vLLM, LocalAI, LM Studio, ...).

    notifier.yaml¶

    # Notifier configuration.
#
# When `telegram:` is set, the daemon talks directly to the Telegram
# Bot API (inline-keyboard approve/reject + threaded replies). Any
# non-`tgram://` Apprise URLs configured alongside it are fanned out
# via a composite outbound (every channel gets the prompt; a
# transient outage on one doesn't tear down the others). A duplicate
# `tgram://` URL is silently dropped to avoid double-prompting.
#
# Apprise URL examples (used only when `telegram:` is unset):
#   tgram://<bot_token>/<chat_id>            # Telegram via Apprise (no inline keyboard)
#   slack://<token_a>/<token_b>/<token_c>    # Slack
#   discord://<webhook_id>/<webhook_token>   # Discord
#   ntfys://<server>/<topic>                 # ntfy

apprise_urls: []

telegram:
  bot_token: ${TELEGRAM_BOT_TOKEN}
  chat_id: ${TELEGRAM_CHAT_ID}

# poll_timeout_s: 30.0

    See NotifierConfig. Outbound has two paths today:

    • When telegram: is set, the daemon talks directly to the Telegram Bot API to ship inline-keyboard approve/reject buttons and threaded reply support. Inbound is wired the same way.
    • When telegram: is unset, outbound flows through Apprise to whichever URLs you configure in apprise_urls.

    Mixing the two ("Telegram direct and Apprise fan-out to Slack at the same time") is a known gap: the bootstrap currently logs a warning and ignores apprise_urls whenever telegram: is set. A composite outbound is a TODO tracked in bootstrap.py. For now pick one delivery mode.

    rules.yaml¶

    # Rule definitions for the deterministic rule engine.
#
# Selection: the dispatcher picks the rule with the highest weight*confidence
# whose `coherence` checks pass; if none pass, control hands off to the LLM.
#
# Rule fields:
#   id                    Stable identifier; auto-generated rules use mined_<hash>.
#   match.filename_regex  Regex; supports inline (?i) for case-insensitive.
#   match.ext             Optional list of extensions, with the leading dot.
#   match.mime_types      Optional list of MIME types.
#   match.content_keywords Optional substrings that must appear in extracted text.
#   destination_template  Path template. {year} is the only placeholder
#                         currently supported; any other placeholder makes
#                         the rule fail to fire.
#   coherence.year_match  When true, the year detected in the file must match
#                         the year placeholder in the destination.
#   weight                Static priority, [0, +inf). Default 1.0.
#   confidence            Learned score in [0, 1]. Default 1.0 for hand rules.
#   anchored              When true, the rule is immune to auto-demote/auto-modify.
#   source                hand | auto_promoted | user_inferred | notifier_confirmed.
#   sample_count          Number of decisions backing the confidence score.

rules:
  # Worked example: route US tax PDFs into per-year folders, but only when the
  # year mentioned in the filename matches the destination's {year} placeholder
  # (the coherence guard prevents 2024 documents from landing in Taxes/2025/).
  - id: tax_pdf_to_year
    match:
      filename_regex: '(?i)\b(tax|irs|1040|w-?2)\b'
      ext: [.pdf]
    destination_template: 'Finance/Taxes/{year}/'
    coherence:
      year_match: true
    weight: 1.0
    anchored: true
    source: hand
    confidence: 1.0
    sample_count: 0

  # Receipts go to a flat folder; cheap, no coherence guard.
  - id: receipts_pdf
    match:
      filename_regex: '(?i)\breceipt\b'
      ext: [.pdf, .jpg, .jpeg, .png]
    destination_template: 'Finance/Receipts/'
    weight: 0.8
    source: hand
    confidence: 1.0
    sample_count: 0

    The rule schema is documented inline; the matcher and scorer arrive in Phase 2.
